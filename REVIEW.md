# REVIEW.md

Review of the starter `app/main.py`. Line numbers refer to the original starter file.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | module, L22-23 | Hard-coded fallbacks `mongodb://localhost:27017` / `attendance_db`. The contract says never hard-code connection details. | Start without `MONGO_URI`: the app silently talks to a different database instead of failing. | Read both from the environment (`.env` only fills gaps). Fail fast with a clear error if either is missing. |
| 2 | module, L22 `MongoClient(...)` | No `tz_aware`, so PyMongo returns **naive** datetimes. Comparing them with IST-aware values raises `TypeError`, and naive maths silently uses the wrong offset. | Punch-out on a record read back from MongoDB gives a 500 (`can't subtract offset-naive and offset-aware datetimes`). | `MongoClient(..., tz_aware=True, tzinfo=UTC)`. All instants are aware UTC internally. |
| 3 | module (missing) | No indexes at startup. There is no unique index on `employees.emp_code` or on `(emp_code, date)`, so nothing enforces uniqueness, and every list/analytics query is a COLLSCAN. | `explain` shows COLLSCAN. Parallel duplicate requests create duplicate documents. | A `lifespan` hook creates the named indexes idempotently (see DECISIONS.md). |
| 4 | `compute_late_minutes`, L35 | The shift start is built with `punch_in.replace(hour, minute)` in the punch-in's own timezone (naive server-local or UTC), not IST. | On a UTC server, a 09:45 IST punch-in (04:15 UTC) is compared with 09:30 UTC, giving 0 instead of 15. | Shift start = `combine(attendance_date, shift_start, IST)`. |
| 5 | `compute_late_minutes`, L36-37 | The grace check uses truncated whole minutes (`minutes > 10`), but R2 says strictly more than 10:00. | 09:40:30 gives `int(10.5) = 10`, which is not `> 10`, so 0. The expected value is 10. | Compare elapsed **seconds** with 600, then floor to minutes. |
| 6 | `compute_late_minutes` | Overnight shifts are ignored: a 00:30 punch-in for a 22:00 shift is compared with 22:00 the same day, which is negative, so 0. | Employee with shift 22:00-06:00 punches in at 00:30: expected `late_minutes` 150, got 0. | `attendance_date()` implements R1 (previous day when before `shift_end`), and the shift start comes from that date. |
| 7 | helpers (all) | Milliseconds are never truncated to whole seconds (R1). | `punched_at` = 09:40:00.900 should not be late and should be stored and returned as 09:40:00.000. | `ms_to_dt()` truncates on input, and the truncated value is stored and returned. |
| 8 | `compute_work_hours`, L41 | `round(x, 2)` is banker's rounding on a binary float, not half-up (R4). | 2 h 07 m 30 s = 2.125 h gives `round(2.125, 2) = 2.12`. The expected value is 2.13. | Integer seconds, `Decimal`, `ROUND_HALF_UP`. |
| 9 | `compute_overtime`, L47 | No 30-minute threshold (R3): any positive difference is returned. | Punch-out 18:35 with shift end 18:30 gives 5. The expected value is 0. | Return the minutes only if >= 30, else 0. |
| 10 | `compute_overtime`, L46 | The overnight shift end is on the start date instead of the next day. A naive `punch_out` minus an aware `end` also raises `TypeError`. | 22:00-06:00 shift, punch-out 06:40 next day: gives 1480 min, expected 40. | `shift_window()` adds a day to the end of overnight shifts. All datetimes are aware. |
| 11 | `EmployeeIn`, L53-60 | No validation: `emp_code` pattern, email, lengths, `HH:MM` shifts, a real `joined_on` date, `shift_start != shift_end`. | `{"shift_start":"abc"}` is accepted and later crashes punch-in with a 500. `joined_on:"2026-02-30"` is stored. | Pydantic constraints matching the OpenAPI schema, plus validators for the date and the equal-shift case. |
| 12 | `PunchInIn`, L65-66 | `punched_at: Optional[int]` is lax: `"1783312500000"`, `1783312500000.0` and seconds values like `1783312500` (a 1970 date) are all accepted. `status` accepts any string, including `ABSENT` and `"FOO"`. | POST with `punched_at: 1783312500` returns 201 with date 1970-01-21. | `EpochMs` = strict int in [1e11, 4102444800000]. `status` is `Literal["PRESENT","WFH","ON_DUTY"]`. |
| 13 | `health`, L72-74 | Always returns 200, even when MongoDB is down. | Stop MongoDB: `/health` still says ok, and the grader starts testing too early. | `ping` MongoDB; on error return 503. |
| 14 | `create_employee`, L79-83 | Check-then-insert race: two concurrent creates both pass `find_one` and both insert. | 10 parallel POSTs with the same `emp_code` give several 201s and duplicate employees. | A unique index decides; `DuplicateKeyError` becomes 409. |
| 15 | `create_employee`, L82/85 | `created_at = datetime.now()` is naive server-local time stored as if it were UTC (shifted by the server offset), and it is returned as an ISO string, not epoch ms. | Response has `"created_at": "2026-10-13T22:30:00"` instead of an integer. | UTC-aware now, truncated to ms, returned via `employee_out()` as epoch ms. |
| 16 | `list_employees`, L93 | `skip = page * page_size` skips the first page entirely. | `page=1` returns employees 21-40. | `skip = (page - 1) * page_size`. |
| 17 | `list_employees`, L94 | `total` counts the whole collection and ignores the department filter (R10). | `?department=Sales` returns `total` = all employees. | `count_documents(query)` with the same filter. |
| 18 | `list_employees`, L95 | No sort, so the order is undefined and pages overlap. No bounds on `page`/`page_size`. | `page=0` gives a negative skip and a 500. `page_size=100000` dumps everything. | `.sort("emp_code")`, `page >= 1`, `1 <= page_size <= 100` (422 otherwise). |
| 19 | `punch_in`, L101/113 | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises `TypeError` and returns a 500. | POST with `emp_code: "EMP9999"` gives 500, expected 404. | `get_employee_or_404()`. |
| 20 | `punch_in`, L102-103 | `datetime.fromtimestamp()` uses the server's local zone, and `ts.date()` is the server-local date, not the IST date (R1). | On a UTC server, a punch-in at 01:00 IST (19:30 UTC the day before) gets yesterday's date. | Convert to IST, then apply R1 (including the overnight rule). |
| 21 | `punch_in`, L104-118 | Check-then-insert race on `(emp_code, date)`. | 10 parallel identical punch-ins give several 201s and duplicate records. Expected: one 201, rest 409. | Unique `(emp_code, date)` index; insert directly and map `DuplicateKeyError` to 409. |
| 22 | `punch_in`, L119-121 | Returns `"id"` (stringified `_id`), which the contract forbids. `punch_in` is returned as a datetime/ISO string, not epoch ms. | Response contains `"id": "6703..."` and `"punch_in": "2026-07-06T09:40:00"`. | `record_out()` builds the exact contract shape: no `_id`, instants as epoch ms. |
| 23 | `list_attendance`, L144-147 | Loads the **whole collection** into memory, then sorts and pages in Python. | Slow and memory-heavy at 100k records; explain shows COLLSCAN. | `find(query).sort(...).skip().limit()` on the `(date desc, emp_code)` index, with `count_documents(query)` for `total`. |
| 24 | `list_attendance`, L145 | Sorted by `date` only; the tie-breaker `emp_code` ascending is missing. | Same-date records come back in insertion order and differ between pages. | Sort `[("date", -1), ("emp_code", 1)]`. |
| 25 | `list_attendance`, L148-149 | Leaks `id` from `_id`, returns ISO datetimes, and legacy records come back without `half_day`/`history`. | Seeded legacy record 9 has no `half_day` key in the response. | `record_out()`: defaults for missing fields, epoch ms, no id. |
| 26 | `list_attendance`, params | No validation: `date_from > date_to`, bad date formats, unknown `status`, `page`/`page_size` bounds. | `?date_from=2026-07-10&date_to=2026-07-01` returns 200 and an empty list, expected 422. `?status=HOLIDAY` returns 200. | Strict date parsing, a 422 when from > to, a `Status` enum, page bounds. |

## Looked at and decided it was fine
- `load_dotenv()` (L20). Its default is `override=False`, so real environment variables already win over `.env`. I made `override=False` explicit for readability.
- `IST = timezone(timedelta(hours=5, minutes=30))` is correct, and India has no DST.
- `doc.pop("_id", None)` after `insert_one` in `create_employee` correctly stops the `_id` that PyMongo adds from leaking (the rest of that function was rewritten for other reasons).
- `int(...)` truncation in `compute_overtime` equals floor for positive values. The real problems there were the threshold and the overnight end.
- `status_code=201` on the two POST endpoints matches the contract.
- Building the `date` range filter with string `$gte`/`$lte` is correct because dates are zero-padded `YYYY-MM-DD` strings.
